# การปฏิบัติตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA)

- **ID:** REQ-20261015-02 (อ้างในข้อความ requirement ว่า REQ-PDPA)
- **วันที่:** 2026-10-15
- **สถานะ:** Superseded — ถูกแทนที่โดย [[../01-requirements/01-spec/20261015-03-pdpa-baseline|REQ-20261015-03]] (ย้ายมา archive 2026-10-15)

## 1. ที่มา / Requirement ดิบ
> ระบบ Grade Runway ต้องคุ้มครองข้อมูลส่วนบุคคลของนักศึกษาและผู้ใช้ทุกกลุ่ม (นักศึกษา, Mentor, อาจารย์, admin) เนื่องจากระบบเก็บข้อมูลอ่อนไหว เช่น ผลการเรียน พฤติกรรมการเรียน และเนื้อหาการสนทนาในแชท
> ระบบต้องมี: (1) ความยินยอม: แสดงประกาศก่อนใช้งาน บันทึกว่าใครยินยอมเมื่อไหร่ และให้ถอนความยินยอมได้ (2) ประกาศความเป็นส่วนตัว: ระบุข้อมูลที่เก็บ วัตถุประสงค์ และผู้ที่เข้าถึงได้ (3) สิทธิเจ้าของข้อมูล: ขอดู ขอแก้ ขอลบ และถอนความยินยอม — เมื่อนักศึกษาขอลบข้อความ ระบบต้องลบเนื้อหาข้อความ แต่คงบันทึกใน Log ว่ามีการลบ (4) ระยะเวลาเก็บ: ข้อความที่อนุมัติแล้วเก็บ 1 ปีการศึกษา ข้อความที่ถูกปฏิเสธเก็บ 90 วัน แล้วลบอัตโนมัติเมื่อครบ (5) เหตุละเมิดข้อมูล: มีขั้นตอนแจ้งผู้รับผิดชอบและเจ้าของข้อมูล (6) ผู้รับผิดชอบข้อมูล: อาจารย์ผู้สอนรายวิชา
> ข้อกำหนดต่อฟีเจอร์: ทุกฟีเจอร์ในระบบต้องระบุ (ก) ข้อมูลส่วนบุคคลที่ฟีเจอร์เก็บ (อ้างถึง REQ-PDPA) (ข) เหตุการณ์ที่ต้องลง Log (อ้างถึง REQ-AUDIT)

## 2. เป้าหมาย
- คุ้มครองข้อมูลส่วนบุคคลและข้อมูลอ่อนไหวของผู้ใช้ทุกกลุ่มตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562
- ให้เจ้าของข้อมูลใช้สิทธิของตนได้ และมีหลักฐานการปฏิบัติตามผ่าน [[20261015-01-audit-logging|REQ-AUDIT]]
- บังคับให้ทุกฟีเจอร์ในอนาคตระบุข้อมูลส่วนบุคคลและเหตุการณ์ Log ตั้งแต่ขั้น spec

## 3. ผู้ใช้ / บทบาทที่เกี่ยวข้อง
| บทบาท | เกี่ยวข้องกับ PDPA อย่างไร |
|-------|----------------------------|
| นักศึกษา | เจ้าของข้อมูลหลัก ให้/ถอนความยินยอม ใช้สิทธิขอดู/แก้/ลบ |
| Mentor | เจ้าของข้อมูล (เป็นผู้ใช้ที่มีข้อมูลบัญชี/ข้อความ) ใช้สิทธิเช่นเดียวกัน |
| อาจารย์ผู้สอนรายวิชา | ผู้รับผิดชอบข้อมูล (data controller) ของรายวิชา รับเรื่องเหตุละเมิดและคำขอใช้สิทธิ |
| Admin | ผู้ดูแลระบบ ดำเนินการตามคำขอ, แจ้งเหตุละเมิดถึงอาจารย์, ดู Log |

## 4. Functional Requirements
| ID | รายละเอียด | Priority (Must/Should/Could) |
|----|------------|------------------------------|
| FR-1 | แสดงประกาศขอความยินยอมก่อนใช้งานครั้งแรก (และเมื่อประกาศเปลี่ยนเวอร์ชัน) ใช้งานต่อไม่ได้หากยังไม่ยินยอม | Must |
| FR-2 | บันทึกการยินยอม: ผู้ใช้, เวลา, เวอร์ชันของประกาศ, ผลลัพธ์ | Must |
| FR-3 | ผู้ใช้ถอนความยินยอมได้ตลอดเวลา ทำได้ง่ายเท่ากับตอนให้ ผลคือ หยุดใช้งานฟีเจอร์ที่ต้องใช้ความยินยอม และคงข้อมูลเดิมตามระยะเก็บ (ลบเพิ่มได้ผ่านคำขอลบ ข้อ FR-6) | Must |
| FR-4 | หน้าประกาศความเป็นส่วนตัว (Privacy Notice): ข้อมูลที่เก็บ, วัตถุประสงค์, ผู้ที่เข้าถึงได้ (ตามบทบาท), ระยะเก็บ, ผู้รับผิดชอบข้อมูล, ช่องทางใช้สิทธิ | Must |
| FR-5 | สิทธิขอดูข้อมูลของตน (ส่งสำเนาข้อมูลที่เกี่ยวข้องกับตน) | Must |
| FR-6 | สิทธิขอลบข้อมูล เมื่อนักศึกษาขอลบข้อความ ระบบลบเนื้อหาข้อความจริง แต่คงรายการ Log ว่ามีการลบ (ไม่มีเนื้อหา) | Must |
| FR-7 | สิทธิขอแก้ข้อมูลที่ไม่ถูกต้อง (ข้อมูลที่มาจาก LMS/ทะเบียนให้ส่งต่อแก้ที่ต้นทาง) | Must |
| FR-8 | ข้อความที่อนุมัติแล้วถูกลบอัตโนมัติเมื่อสิ้นปีการศึกษาที่อนุมัติ | Must |
| FR-9 | ข้อความที่ถูกปฏิเสธถูกลบอัตโนมัติเมื่อครบ 90 วัน นับจากวันที่ปฏิเสธ | Must |
| FR-10 | ขั้นตอนเหตุละเมิดข้อมูล: admin แจ้งอาจารย์ผู้รับผิดชอบภายใน 24 ชั่วโมงหลังรับทราบเหตุ แล้วอาจารย์/มหาวิทยาลัยแจ้งเจ้าของข้อมูลและหน่วยงานกำกับตามกรอบกฎหมาย (72 ชม.) และมีบันทึกเหตุการณ์ (incident record) | Must |
| FR-11 | ระบุอาจารย์ผู้สอนรายวิชาเป็นผู้รับผิดชอบข้อมูลของรายวิชา แสดงในประกาศความเป็นส่วนตัวและเชื่อมกับการแจ้งเหตุละเมิด | Must |
| FR-12 | ทุกสเปกฟีเจอร์ต้องมีหัวข้อ "ข้อมูลส่วนบุคคลที่เก็บ" และ "เหตุการณ์ที่ลง Log" (ใช้เป็น checklist ใน Definition of Done / review สเปก) | Must |
| FR-13 | การดูข้อมูลส่วนบุคคลอ่อนไหว (เกรด/GPA, ข้อความ) จำกัดตามบทบาทและ "need to know" | Must |
| FR-14 | ติดตามคำขอใช้สิทธิ (request ID, สถานะ, ผู้ดำเนินการ, กำหนดเสร็จ) | Should |
| FR-15 | ลบ Log ที่มีข้อมูลส่วนบุคคลตามระยะเก็บของ REQ-AUDIT (1 ปี) และระบุใน Privacy Notice | Must |

## 5. Non-functional Requirements
- **ความปลอดภัย:** เข้ารหัสข้อมูลระหว่างส่งและขณะเก็บ (ข้อมูลอ่อนไหว) และควบคุมสิทธิตามบทบาท (ระดับมาตรการจะกำหนดในเอกสารออกแบบ)
- **การลบจริง:** การลบเนื้อหาต้องลบจากที่เก็บหลักและ backup ตามรอบที่กำหนด (ยังเปิดอยู่ในข้อ 10)
- **การพิสูจน์ได้ (accountability):** การให้/ถอนความยินยอม การใช้สิทธิ การลบ ต้องตรวจสอบย้อนหลังได้ผ่าน Log
- **ความสามารถใช้งานได้:** ประกาศและคำขอใช้สิทธิเป็นภาษาไทย อ่านเข้าใจง่าย

## 6. Business Rules
- ผู้ใช้ทุกกลุ่มต้องยินยอมก่อนใช้งาน ถอนได้ตลอดเวลา
- ถอนความยินยอม = หยุดใช้งาน + คงข้อมูลเดิมตามระยะเก็บ (ไม่ลบอัตโนมัติ ต้องยื่นขอลบเอง)
- ข้อความอนุมัติแล้ว: เก็บถึงสิ้นปีการศึกษาที่อนุมัติ → ลบอัตโนมัติ
- ข้อความถูกปฏิเสธ: เก็บ 90 วัน (นับจากวันปฏิเสธ) → ลบอัตโนมัติ
- ขอลบข้อความ: ลบเนื้อหาทันทีตามคำขอที่ยืนยันสิทธิแล้ว แต่ Log ว่ามีการลบต้องคงอยู่
- Log กิจกรรมไม่เก็บเนื้อหาข้อความ/ค่าเกรด และอายุ 1 ปี (ดู REQ-AUDIT)
- ผู้รับผิดชอบข้อมูล = อาจารย์ผู้สอนรายวิชา
- เหตุละเมิด: admin → อาจารย์ผู้รับผิดชอบ (≤24 ชม.) → เจ้าของข้อมูล/หน่วยงานกำกับ

### ตารางระยะเก็บข้อมูล
| ข้อมูล | ระยะเก็บ | การลบ |
|--------|----------|--------|
| ข้อความแชทที่อนุมัติ | ถึงสิ้นปีการศึกษาที่อนุมัติ | อัตโนมัติ |
| ข้อความแชทที่ถูกปฏิเสธ | 90 วันนับจากวันปฏิเสธ | อัตโนมัติ |
| Log กิจกรรม | 1 ปีนับจากเวลาของรายการ | อัตโนมัติ |
| บันทึกความยินยอม | ยังไม่กำหนด (ดูข้อ 10) | — |
| ผลการเรียน/ข้อมูลที่ซิงก์จาก LMS | ยังไม่กำหนด (ดู REQ-20261014-01 ข้อ 10) | — |

## 7. ขอบเขต
- **In scope:** ระบบความยินยอม, Privacy Notice, ช่องทางใช้สิทธิ (ขอดู/แก้/ลบ/ถอนความยินยอม), ระยะเก็บและลบอัตโนมัติของข้อความ, ขั้นตอนเหตุละเมิด, ระบุผู้รับผิดชอบข้อมูล, กฎ "ต่อฟีเจอร์"
- **Out of scope (assumption):** การแต่งตั้ง DPO อย่างเป็นทางการและนโยบายระดับมหาวิทยาลัย, การแจ้งหน่วยงานกำกับจริง (เป็นกระบวนการนอกระบบ), สิทธิคัดค้าน/โอนย้ายข้อมูล (data portability) ในเฟสนี้, ข้อตกลงกับผู้ประมวลผลภายนอก, การทำ DPIA

## 8. Acceptance Criteria
- AC-1: ผู้ใช้ที่ยังไม่ยินยอมเข้าใช้ฟีเจอร์หลักไม่ได้ และเมื่อยินยอมมีบันทึกผู้ใช้/เวลา/เวอร์ชันประกาศ
- AC-2: ผู้ใช้ถอนความยินยอมแล้วใช้ฟีเจอร์ที่ต้องยินยอมต่อไม่ได้ ข้อมูลเดิมยังอยู่ตามระยะเก็บ และมี Log
- AC-3: หน้า Privacy Notice แสดงข้อมูลที่เก็บ วัตถุประสงค์ ผู้เข้าถึง ระยะเก็บ ผู้รับผิดชอบข้อมูล ครบทุกหัวข้อ
- AC-4: นักศึกษาขอลบข้อความ → เนื้อหาหายจากระบบ (ผู้ส่ง ผู้ตรวจ ผู้รับ) แต่ Log มีรายการว่าลบ ไม่มีเนื้อหา
- AC-5: ข้อความที่ถูกปฏิเสธครบ 90 วัน ถูกลบอัตโนมัติ; ข้อความที่อนุมัติถูกลบเมื่อสิ้นปีการศึกษาที่อนุมัติ; ที่ยังไม่ครบกำหนดยังอยู่
- AC-6: เหตุละเมิดที่บันทึก มีขั้นตอนแจ้งอาจารย์ผู้รับผิดชอบภายใน 24 ชม. และบันทึกการแจ้งเจ้าของข้อมูล
- AC-7: ทุกสเปกฟีเจอร์ในโฟลเดอร์ 01-spec มีหัวข้อข้อมูลส่วนบุคคลและเหตุการณ์ Log (ผ่านการ review)
- AC-8: เจ้าของข้อมูลยื่นคำขอดู/แก้/ลบได้ และเห็นสถานะคำขอ

## 9. Assumptions และคำตอบที่ได้จากผู้ใช้
**คำตอบจากผู้ใช้**
| คำถาม | คำตอบ |
|-------|-------|
| "เก็บ 1 ปีการศึกษา" นับจากเมื่อไหร่ | สิ้นปีการศึกษาที่อนุมัติ |
| เมื่อถอนความยินยอมต้องทำอย่างไร | หยุดใช้งาน + คงข้อมูลเดิมตามระยะเก็บ |
| เพิ่มหัวข้อ PDPA/Log ในสเปกเดิม 2 ฉบับหรือไม่ | เพิ่มหัวข้อสั้น ๆ ทั้ง 2 ฉบับ |
| ขั้นตอนแจ้งเหตุละเมิด | admin แจ้งอาจารย์ผู้รับผิดชอบภายใน 24 ชม. แล้วแจ้งเจ้าของข้อมูล |

**Assumptions**
- ฐานทางกฎหมายหลักของระบบคือความยินยอม (ตามที่ requirement ระบุ) ฐานอื่น (เช่น ภารกิจของสถาบัน) ยังไม่วิเคราะห์ในเอกสารนี้
- "ปีการศึกษา" ใช้ตามปฏิทินวิชาการของสถาบัน ต้องมีข้อมูลวันสิ้นปีการศึกษาให้ระบบอ่านได้
- ถอนความยินยอมไม่ทำให้ข้อมูลที่เก็บไปแล้วเสียความชอบด้วยกฎหมาย แต่ผู้ใช้ยังยื่นขอลบได้เสมอ
- กรอบเวลา 72 ชม. ที่กฎหมายกำหนดนับจากที่ผู้ควบคุมข้อมูลรับทราบเหตุ จึงตั้งให้ admin แจ้งภายใน 24 ชม. เพื่อเหลือเวลาประเมิน (ควรให้ฝ่ายกฎหมายยืนยัน)
- คำขอใช้สิทธิต้องยืนยันตัวตนผู้ขอก่อนดำเนินการ
- คำขอลบข้อความของนักศึกษา ใช้กับข้อความที่ตนเป็นผู้ส่ง

## 10. คำถามที่ยังเปิดอยู่
- ผู้ใช้ 1 คนอยู่หลายรายวิชา → ผู้รับผิดชอบข้อมูลหลายคน ใครรับคำขอ/เหตุละเมิดเมื่อข้อมูลข้ามรายวิชา (เช่น ข้อความแชท, Log)
- ระยะเก็บของบันทึกความยินยอม, ข้อมูลผลการเรียนที่ซิงก์จาก LMS, ข้อมูลบัญชีผู้ใช้
- ผู้ใช้ที่เป็นผู้เยาว์ (ถ้ามีนักศึกษาอายุต่ำกว่า 20 ปี) ต้องขอความยินยอมจากผู้ปกครองหรือไม่
- กำหนดเวลาตอบคำขอใช้สิทธิ (ค่าอ้างอิงตามกฎหมายคือภายใน 30 วัน)
- ข้อความที่ถูกลบแล้ว แต่ถูกอนุมัติและผู้รับอ่านไปแล้ว มีผลต่อผู้รับอย่างไร และ backup ลบเมื่อไหร่
- ถ้าใช้ AI วิเคราะห์ข้อความ (REQ-20261014-02 FR-8) ต้องแจ้งใน Privacy Notice และตรวจเรื่องส่งข้อมูลออกนอกระบบ/ต่างประเทศ
- ถอนความยินยอมของผู้ตรวจ/อาจารย์/admin (ผู้ใช้ที่ทำหน้าที่ตามสัญญา/หน้าที่) ใช้ได้เหมือนนักศึกษาหรือไม่
- ผู้ใช้ที่ถอนความยินยอมแล้ว ข้อความที่ส่งไว้และกำลังรออนุมัติ จะถูกดำเนินการต่อหรือไม่
- Privacy Notice ต้องมีเวอร์ชัน/อนุมัติโดยใคร
