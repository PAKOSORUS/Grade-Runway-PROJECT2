# PDPA Baseline: การปฏิบัติตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562

- **ID:** REQ-20261015-03 (ใช้อ้างอิงสั้น ๆ ว่า REQ-PDPA แทนฉบับเดิม REQ-20261015-02)
- **วันที่:** 2026-10-15
- **สถานะ:** Draft

## 1. ที่มา / Requirement ดิบ
> ระบบ Grade Runway ต้องปฏิบัติตาม พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA) เป็นข้อกำหนดพื้นฐาน (baseline) ที่ทุกฟีเจอร์ต้องปฏิบัติตาม โดยเฉพาะ 2 ฟีเจอร์ที่ประมวลผลข้อมูลส่วนบุคคลของนักศึกษา: ระบบติดตามและแจ้งเตือนความเสี่ยงการเรียน (risk-alert) และช่องแชทแนะนำแนวทางการเรียนระหว่างนักศึกษา (peer-advice-chat) กลไกบันทึก Log ที่ใช้เป็นหลักฐานกำหนดแยกไว้ใน [[20261015-01-audit-logging|REQ-AUDIT]]
> (รายละเอียดครบถ้วนตามข้อความที่ผู้ใช้ส่งมา สรุปไว้ในข้อ 4–8 ด้านล่าง)

## 2. เป้าหมาย
- ให้ทั้งสองฟีเจอร์ประมวลผลข้อมูลส่วนบุคคลบนฐานกฎหมายที่ถูกต้อง โปร่งใส และจำกัดตามความจำเป็น
- ให้เจ้าของข้อมูลใช้สิทธิตามกฎหมายได้ และสถาบันมีกระบวนการรองรับ รวมถึงเหตุละเมิดข้อมูล
- ใช้เป็นข้อกำหนดพื้นฐานของฟีเจอร์ทุกตัวในอนาคต

## 3. ผู้ใช้ / บทบาทที่เกี่ยวข้อง
| บทบาท | เกี่ยวข้องอย่างไร |
|-------|------------------|
| นักศึกษา | เจ้าของข้อมูล ให้/ถอนความยินยอม (แชท) ใช้สิทธิ ขอคัดค้านการประเมินความเสี่ยง |
| อาจารย์ที่ปรึกษา | เห็นข้อมูลความเสี่ยงเฉพาะนักศึกษาในความดูแล |
| ผู้ตรวจข้อความ (อาจารย์/admin) | เข้าถึงข้อความเพื่อการตรวจเท่านั้น |
| Admin | ดำเนินการตามคำขอ ใช้ MFA |
| สถาบันการศึกษา | Data Controller |
| ทีมพัฒนา/ผู้ให้บริการ Grade Runway | Data Processor |

## 4. Functional Requirements
| ID | รายละเอียด | Priority |
|----|------------|----------|
| FR-1 | Privacy notice แยกตามฟีเจอร์ แสดงก่อน/ขณะเก็บข้อมูล ระบุข้อมูลที่เก็บ วัตถุประสงค์ ฐานทางกฎหมาย ผู้เข้าถึง ระยะเก็บ ภูมิภาคจัดเก็บ และการส่งข้อมูลไปต่างประเทศ (ถ้ามี) | Must |
| FR-2 | ก่อนใช้แชทครั้งแรก ต้องกดยินยอมอย่างชัดแจ้ง บันทึกผู้ยินยอม/เวลา และถอนความยินยอมได้ | Must |
| FR-3 | ถอนความยินยอมแชทต้องไม่กระทบ risk-alert (ฐานภารกิจทางการศึกษา); ข้อความของผู้ถอนที่ยังรออนุมัติถูกยกเลิกไม่ส่ง | Must |
| FR-4 | รองรับสิทธิ: เข้าถึง แก้ไข ลบ ถอนความยินยอม คัดค้านการประมวลผล และโอนย้ายข้อมูล (ไฟล์ JSON + CSV ดาวน์โหลดผ่านคำขอ) พร้อมกระบวนการรับคำร้อง | Must |
| FR-5 | นักศึกษาดูได้ว่าถูกแจ้งเตือนความเสี่ยงเพราะกฎ/เงื่อนไขใด และขอคัดค้านการประเมินได้ อาจารย์ที่ปรึกษาเป็นผู้พิจารณาภายใน 7 วัน ระบบพักการแจ้งเตือนที่ถูกคัดค้านระหว่างรอผล หากไม่ตอบใน 7 วันให้พักการแจ้งเตือนต่อได้และแจ้ง DPO | Must |
| FR-6 | ขอลบข้อความแชท: ลบเนื้อหา แต่คงบันทึกใน Log ว่ามีการลบ | Must |
| FR-7 | จำกัดการเข้าถึงตามบทบาท: นักศึกษาเห็นเกรด/ความเสี่ยงของตนเท่านั้น; อาจารย์ที่ปรึกษาเห็นเฉพาะนักศึกษาในความดูแล; ผู้ตรวจเห็นข้อความเพื่อการตรวจเท่านั้น | Must |
| FR-8 | ข้อความแชทที่ยังไม่ผ่านการอนุมัติต้องไม่ถึงผู้รับในทุกช่องทาง | Must |
| FR-9 | อีเมลแจ้งเตือนห้ามระบุเกรดหรือรายละเอียดความเสี่ยง ใช้ข้อความทั่วไปพร้อมลิงก์เข้าสู่ระบบ | Must |
| FR-10 | ข้อมูลเกรด/GPA ที่ใช้คัดสิทธิ์ผู้ส่งข้อความ (ถ้ามี) ห้ามแสดงให้นักศึกษาคนอื่นเห็น | Must |
| FR-11 | การบังคับสิทธิ์ทำที่ฝั่งฐานข้อมูล ไม่ใช่แค่ซ่อนปุ่มในหน้าจอ | Must |
| FR-12 | แสดงคำเตือนก่อนส่งข้อความแชท ไม่ให้ใส่ข้อมูลส่วนบุคคลของตนหรือผู้อื่น โดยเฉพาะข้อมูลอ่อนไหว (เช่น สุขภาพ) | Must |
| FR-13 | ผู้ตรวจต้องปฏิเสธหรือขอให้แก้ข้อความที่อ้างถึงข้อมูลส่วนบุคคลของผู้อื่น; ข้อความที่อนุมัติแล้วแต่พบภายหลัง ผู้ตรวจถอนเนื้อหาได้ | Must |
| FR-14 | ลบ/ทำให้ไม่ระบุตัวตนข้อมูลอัตโนมัติตามตารางระยะเก็บ (ข้อ 6) รวมสำเนา backup ของข้อมูลที่ลบ/ถอนเนื้อหาต้องถูกหมุนทับภายใน 30 วัน | Must |
| FR-15 | กระบวนการเหตุละเมิดข้อมูล: ตรวจจับ ประเมินความรุนแรง แจ้ง สคส. และ/หรือเจ้าของข้อมูลภายใน 72 ชม. นับจากทราบเหตุ | Must |
| FR-16 | เข้ารหัสข้อมูลขณะจัดเก็บและส่งผ่าน, least privilege, admin ต้องใช้ MFA | Must |
| FR-17 | ทุกสเปกฟีเจอร์ต้องมีหัวข้อ "ข้อมูลส่วนบุคคลที่เก็บ" และ "เหตุการณ์ที่ลง Log" (checklist ใน review/DoD) — คงจากฉบับเดิม | Must |
| FR-18 | ติดตามคำขอใช้สิทธิ (request ID สถานะ ผู้ดำเนินการ กำหนดเสร็จ) — คงจากฉบับเดิม | Should |

## 5. Non-functional Requirements
- ความปลอดภัย: ดู FR-16; ระบุภูมิภาคจัดเก็บข้อมูลและการส่งข้อมูลไปต่างประเทศใน privacy notice
- การตรวจสอบย้อนหลัง: การให้/ถอนความยินยอม การใช้สิทธิ การลบ ต้องมีหลักฐานผ่าน [[20261015-01-audit-logging|REQ-AUDIT]]
- ภาษา: ประกาศและคำขอใช้สิทธิเป็นภาษาไทย อ่านเข้าใจง่าย

## 6. Business Rules
### 6.1 ฐานทางกฎหมาย
| ข้อมูล | ฟีเจอร์ | ฐานทางกฎหมาย |
|---|---|---|
| ผลการเรียน การเข้าเรียน การส่งงาน (LMS/ทะเบียน) | risk-alert | ภารกิจ/สัญญาทางการศึกษา |
| ผลประเมินความเสี่ยงและคำแนะนำเฉพาะบุคคล | risk-alert | ภารกิจ/สัญญาทางการศึกษา |
| อีเมลสำหรับแจ้งเตือน | risk-alert | ภารกิจ/สัญญาทางการศึกษา |
| เนื้อหาข้อความแชท ป้ายเชิงลบ/ไม่เชิงลบ ผลการตรวจ | peer-advice-chat | ความยินยอม |

### 6.2 ระยะเวลาการเก็บ
| ข้อมูล | ระยะเวลา | สถานะ |
|---|---|---|
| ข้อมูลส่วนบุคคลของนักศึกษา | ตลอดสถานภาพ + 5 ปีหลังจบ/พ้นสถานภาพ แล้วลบหรือทำให้ไม่ระบุตัวตน (เว้นแต่ระเบียบทะเบียนกำหนดนานกว่า เช่น ทรานสคริปต์) | ตัดสินใจแล้ว |
| Log กิจกรรม | 1 ปี (configurable) | ตัดสินใจแล้ว |
| ข้อความแชทที่อนุมัติแล้ว | ถึงสิ้นปีการศึกษาที่อนุมัติ แล้วลบอัตโนมัติ | ตัดสินใจแล้ว |
| ข้อความแชทที่ถูกปฏิเสธ | 90 วัน แล้วลบอัตโนมัติ | ตัดสินใจแล้ว |
| ผลประเมินความเสี่ยงและประวัติแจ้งเตือน | ตลอดสถานภาพ แล้วลบหรือทำให้ไม่ระบุตัวตนเมื่อพ้นสถานภาพ | ตัดสินใจแล้ว |
| บันทึกความยินยอมและหลักฐานการลบ | ตลอดสถานภาพ + 5 ปี เก็บแยกจาก Log กิจกรรม 1 ปี (รายการ "ลบข้อมูล" ใน Log กิจกรรมคงอายุ 1 ปีตามปกติ ไม่ขยาย) | ตัดสินใจแล้ว |
| IP ของ login ไม่สำเร็จ (ใน Log) | ไม่เกิน 90 วัน | ตัดสินใจแล้ว |
| สำเนา backup ของข้อมูลที่ลบ/ถอนเนื้อหา | หมุนทับภายใน 30 วัน | ตัดสินใจแล้ว |

### 6.3 กฎอื่น
- สิทธิลบข้อความ: ลบเนื้อหา คง Log ว่ามีการลบ
- Data Controller = สถาบันการศึกษา (มหาวิทยาลัย); Data Processor = ทีมพัฒนา/ผู้ให้บริการ ประมวลผลตามขอบเขตที่สถาบันกำหนด
- การนำข้อมูลจาก LMS/ทะเบียนมาใช้ ต้องตรงตามวัตถุประสงค์ที่สถาบันกำหนด

## 7. ขอบเขต
- **In scope:** นโยบายและกลไกรองรับฐานกฎหมาย ความยินยอม สิทธิเจ้าของข้อมูล, การจำกัดการเข้าถึงตามบทบาท, ระยะเก็บและการลบ/ทำให้ไม่ระบุตัวตน, มาตรการความปลอดภัยพื้นฐาน, กระบวนการแจ้งเหตุรั่วไหลระดับนโยบาย
- **Out of scope:** สถาปัตยกรรมเทคนิค (ไปที่ [[../../02-design/02-technical/index|02-technical]]), การร่าง privacy policy ฉบับสมบูรณ์และสัญญาประมวลผลข้อมูล (ฝ่ายกฎหมาย/ผู้เชี่ยวชาญ PDPA), กฎหมายต่างประเทศ (เช่น GDPR)

## 8. Acceptance Criteria
- AC-1: ผู้ใช้เห็น privacy notice ของแต่ละฟีเจอร์ครบหัวข้อ รวมฐานทางกฎหมาย
- AC-2: ผู้ที่ยังไม่ยินยอมใช้แชทไม่ได้ และมีบันทึกผู้ยินยอม/เวลา; ผู้ถอนความยินยอมใช้แชทไม่ได้ แต่ยังได้รับ risk-alert ตามปกติ
- AC-3: นักศึกษาเห็นเหตุผล/กฎที่ทำให้ถูกแจ้งเตือนและยื่นคัดค้านได้
- AC-4: ขอลบข้อความ → เนื้อหาหายจากระบบ แต่ Log มีรายการว่าลบ
- AC-5: นักศึกษาเห็นเกรด/ความเสี่ยงของตนเองเท่านั้น; อาจารย์ที่ปรึกษาเห็นเฉพาะในความดูแล; ทดสอบที่ระดับฐานข้อมูล (เรียก API/query ตรงก็ถูกปฏิเสธ)
- AC-6: ข้อความที่ยังไม่อนุมัติไม่ปรากฏแก่ผู้รับทุกช่องทาง (รวมอีเมล/แจ้งเตือน)
- AC-7: อีเมลแจ้งเตือนไม่มีเกรด/รายละเอียดความเสี่ยง
- AC-8: ข้อมูลถูกลบ/ทำให้ไม่ระบุตัวตนเมื่อครบระยะเก็บตามตาราง และที่ยังไม่ครบยังอยู่
- AC-9: มีขั้นตอนเหตุละเมิดที่แจ้งภายใน 72 ชม. และบันทึก incident
- AC-10: บัญชี admin ต้องผ่าน MFA

## 9. Assumptions และคำตอบที่ได้จากผู้ใช้
**คำตอบจากผู้ใช้ (รอบนี้)**
| คำถาม | คำตอบ |
|-------|-------|
| ผู้ควบคุมข้อมูล (ฉบับเดิม: อาจารย์ผู้สอนรายวิชา) | มหาวิทยาลัยเป็น Controller |
| ฐานกฎหมาย (ฉบับเดิม: ยินยอมทุกฟีเจอร์) | ตามฉบับใหม่: risk-alert ใช้ภารกิจการศึกษา, แชทใช้ความยินยอม |
| วิธีจัดการ REQ-20261015-02 เดิม | ไม่ระบุ → ใช้ค่าแนะนำ: แทนที่ (ย้ายไป archive) |
| กรอบแจ้งเหตุ/เก็บข้อความอนุมัติ | ไม่ระบุ → ใช้ค่าแนะนำ (ดูด้านล่าง) |
| ข้อความอนุมัติแล้ว "1 ปีการศึกษา" นับอย่างไร (รอบถามซ้ำ) | ถึงสิ้นปีการศึกษาที่อนุมัติ (ยืนยันแล้ว) |
| ผู้รับคำขอใช้สิทธิและเหตุละเมิดฝั่งมหาวิทยาลัย + SLA | DPO/ฝ่ายคุ้มครองข้อมูลกลาง, SLA 30 วัน |
| การคัดค้านการประเมินความเสี่ยง | อาจารย์ที่ปรึกษาพิจารณา และระบบพักการแจ้งเตือนระหว่างรอ |
| ระยะเก็บข้อความปฏิเสธ/ผลประเมิน | ปฏิเสธ 90 วัน / ผลประเมินตลอดสถานภาพแล้วลบ |
| รูปแบบโอนย้ายข้อมูล | ไฟล์ JSON + CSV ดาวน์โหลดผ่านคำขอ |
| ระยะเก็บบันทึกความยินยอม | ตลอดสถานภาพ + 5 ปี แยกจาก Log 1 ปี |
| ข้อความรออนุมัติของผู้ถอนความยินยอม / อนุมัติแล้วพบข้อมูลผู้อื่น | รอ = ยกเลิกไม่ส่ง / อนุมัติแล้ว = ผู้ตรวจถอนเนื้อหา |
| ผู้เยาว์ (<20 ปี) กับแชท | ให้ฝ่ายกฎหมายยืนยันก่อน ตอนนี้ถือว่ายินยอมเองได้ |
| ผู้เยาว์ยินยอมแชทเอง (ยืนยันซ้ำ รอบ 2026-10-15 10:06) | ยินยอมเองได้ รอฝ่ายกฎหมายยืนยัน |
| backup ของข้อมูลที่ลบ/ถอนเนื้อหา | หมุนทับภายใน 30 วัน |
| เวลาพิจารณาคำคัดค้านและกรณีไม่ตอบ | 7 วัน; ไม่ตอบ = พักแจ้งเตือนต่อได้ + แจ้ง DPO |
| การแต่งตั้ง DPO | ยังไม่แต่งตั้ง ถือเป็นงานนอกระบบ (action item) |
| AI วิเคราะห์ข้อความ | ไม่ใช้ในเฟสแรก จึงยังไม่ต้องระบุ AI/ส่งข้อมูลต่างประเทศใน privacy notice |
| หลักฐานการลบใน Log หมดอายุ 1 ปี | ไม่ขยาย คง 1 ปี (หลักฐานระยะยาวใช้บันทึกแยกตาม 6.2) |
| IP login ไม่สำเร็จ | เก็บได้ไม่เกิน 90 วัน |

**Assumptions**
- แจ้งเหตุละเมิด: ตามกฎหมาย ≤72 ชม.; ภายในแนะนำให้ admin แจ้งผู้รับผิดชอบของมหาวิทยาลัย ≤24 ชม. เพื่อเหลือเวลาประเมิน (คงแนวคิดจากฉบับเดิม; ผู้รับผิดชอบฝั่งมหาวิทยาลัยต้องกำหนด)
- ผู้เยาว์ (<20 ปี) ถือว่ายินยอมแชทเองได้ จนกว่าฝ่ายกฎหมายยืนยันเป็นอย่างอื่น
- คำขอใช้สิทธิและเหตุละเมิดฝั่งมหาวิทยาลัยส่งถึง DPO/ฝ่ายคุ้มครองข้อมูลกลาง (ต้องมีผู้ถูกแต่งตั้งจริงนอกระบบ)
- ข้อความปฏิเสธนับ 90 วันจากวันที่ปฏิเสธ
- ปีการศึกษาใช้ตามปฏิทินวิชาการของสถาบัน
- ถอนความยินยอมแล้วข้อมูลเดิมคงอยู่ตามระยะเก็บ จนกว่าผู้ใช้ยื่นขอลบ (คงจากฉบับเดิม)
- คำขอใช้สิทธิต้องยืนยันตัวตนก่อนดำเนินการ
- ขอบเขตผู้ใช้: ฉบับนี้พูดถึงนักศึกษา อาจารย์ที่ปรึกษา ผู้ตรวจ admin; Mentor = นักศึกษาผ่านเกณฑ์ GPA ≥ 3.25 (ยืนยันแล้วใน REQ-20261014-02)
- ผู้ส่งแชทเป็นนิรนามต่อผู้รับ แต่ผู้ตรวจและ Log ระบุตัวผู้ส่งได้ — ต้องระบุใน privacy notice ของแชท
- ยังไม่มี DPO ที่ถูกแต่งตั้ง: ถือเป็นงานนอกระบบ (action item ของมหาวิทยาลัย) ระบบเพียงส่งเรื่องถึงช่องทางที่ DPO ใช้
- สิทธิคัดค้านและโอนย้ายข้อมูลอยู่ในขอบเขตแล้ว (ฉบับเดิมถือว่า out of scope)

## 10. คำถามที่ยังเปิดอยู่
- ฝ่ายกฎหมายยืนยันเรื่องผู้เยาว์ (<20 ปี) กับความยินยอมแชท และกรอบเวลา 72 ชม.
- ต้องมีผู้ถูกแต่งตั้งเป็น DPO/ฝ่ายคุ้มครองข้อมูลกลางจริง (นอกระบบ — action item ของมหาวิทยาลัย; ตอนนี้ยังไม่แต่งตั้ง ซึ่งกระทบ FR-4, FR-5, FR-15)
- ถ้าเปิดใช้ AI (REQ-20261014-02 FR-8) ภายหลัง ต้องกลับมาแจ้งใน privacy notice และตรวจการส่งข้อมูลนอกระบบ/ต่างประเทศ (ตอนนี้ไม่ใช้ในเฟสแรก)

ตอบแล้ว: backup (หมุนทับ 30 วัน), เวลาพิจารณาคำคัดค้าน (7 วัน แล้วพักต่อได้+แจ้ง DPO)
